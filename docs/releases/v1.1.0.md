# NeonDiff 1.1.0

## Version

`1.1.0` / `v1.1.0`. Publication is pending until the release workflow succeeds.

## Release path (lean)

Follow the [lean release checklist](../release-governance.md#lean-release-path-110-and-later).
`release-npm.yml` requires exact-tag CI, publishes with provenance, verifies
signatures and attestation, and confirms the npm shasum and `latest` channel.
The 1.0.x candidate ledger is not required.

## Install

After publication and channel verification: `npm install -g neondiff@1.1.0`.

## Rollback

An owner runs `npm dist-tag add neondiff@<previous> latest`, then verifies
`npm view neondiff dist-tags.latest --prefer-online`. Use an already-verified
immutable predecessor. Existing installs require an explicit version install.

## Product changes

### New
- **GitHub Actions mode.** `neondiff review-pr --ci` reviews the pull request from the Actions event with only `GITHUB_TOKEN` and an OpenAI key. It needs no config file, no GitHub App and no license for public repositories. It posts one review per head with an attribution footer. (#1163)
- **Free review for public repositories, with no license key**, in the GitHub Action, `review-pr --ci` and the self-hosted worker (`daemon`, `run-once`, `review-pr`, `providers verify`). The Mac app follows in the Desktop beta (#1203). Private, internal and unknown-visibility repositories need an active Solo or Team license; a worker without one reviews the public repositories and skips the rest with a clear reason. (#1171, #1208)
- **Restricted review for outside contributors** on public and unknown-visibility repositories: no shell, skills, hooks, web search or image tools, no project docs, and checkout-only reads under a Codex permission profile. If that can't be guaranteed (an older Codex, or a configured backend that can't be confined), the review is skipped with a visible reason, never run unrestricted. (#1207)
- **Private repositories in CI.** One license covers one GitHub organization or user account. The key is read from a runner-owned 0600 file, never from argv or the environment. (#1180)
- **Checkout reads, on by default.** Codex can read the PR checkout to confirm findings outside the changed lines; every cited excerpt is checked against the file. Reads are confined to the checkout by a Codex permission profile. With Codex older than 0.163.0, or if confinement is unavailable, the review falls back to diff-only with a warning. (#1177, #1184)
- **`review-local`** reviews a local diff without a live PR, and comes with a native ReviewBench runner. (#1179)
- **Recall-oriented review prompt.** It finds more real issues: on a 25-PR ReviewBench test set, NeonDiff on `gpt-6.1-sol` scored grounded F1 0.36–0.37 against 0.24–0.25 for native Codex on the same model. Recall is higher (0.22–0.23 vs 0.14–0.15) and precision slightly lower (0.92–0.93 vs 0.96–0.98). Two independent judges agree: GLM and Claude Opus. This is an internal run, not the official leaderboard. (#1185)

### Changed
- **Default model:** `gpt-6.1-sol` at high effort, with a 500k context window. Each review records its Codex usage (model, effort, tokens, time). (#1162)
- **Public-repo author gate.** With ChatGPT-login auth on a public repository, NeonDiff reviews only PRs from owners, members, collaborators and allowlisted bots. Other PRs are skipped with a visible reason. (#1162)
- **Unconfirmed P0/P1 findings** are lowered to P2 instead of dropped. (#1172)
- **No re-posting of answered findings.** NeonDiff does not re-post a finding that a human already answered. (#1170)
- **No re-review after a base merge.** A push that only merges the base branch (verified by recomputing the merge tree) reuses the previous review. (#1182)
- **Secret-like model output is redacted** instead of failing the review. (#1183)

### Fixed
- The daemon reviews pull requests automatically again, and one repository whose pull listing fails no longer stops discovery for the rest. (#1178)
- **Private repositories in CI:** the review checkout (including Git LFS) is authenticated with the workflow token, passed only through git's environment. (#1204)
- The documented Actions workflow runs one review at a time per pull request. (#1205)
- **Checkout reads fail closed:** they turn off, and the review runs diff-only with a warning, when confinement cannot be proven: an unsupported platform, sensitive paths inside the sandbox, or a checkout whose git config (including `config.worktree` and includes) holds credentials. PR-controlled PATH entries are never used to find `codex`. `review-local` with reads on requires a clean checkout. (#1204, #1205)
- **Linux hosts:** before using checkout reads, NeonDiff checks that the Codex sandbox can start. Ubuntu 23.10 and later, and most Docker containers, block the user namespaces it needs; allow them (`sysctl kernel.apparmor_restrict_unprivileged_userns=0`), or reviews run diff-only with a warning. The documented Actions workflow includes the step. (#1212)
- **Issue analysis** reads only the repository source snapshot, under the same Codex permission profile as checkout reads; when that cannot be proven, the analysis fails closed and nothing is posted. (#1209)
- **Related context** for a public repository cites only public repositories. (#1210)
- Proof negation is scoped to its own line or sentence. (#1168)
- Dependency refresh for runtime and dev advisories. (#1194)

### Release
- npm releases from 1.1.0 use a short, auditable workflow: CI must be green on the tag, the publish carries provenance, and the registry read-back must match the packed bytes before `latest` moves. A retry never moves `latest` backward, release tags must be annotated, and the registry's SHA-512 integrity must match. (#1201)

### Known limitations
- The Mac app still asks for a license key on public repositories; keyless public review there follows in the Desktop beta (#1203).
- `review-local` treats the checkout as trusted; run it only on code you would run Codex on directly (#1206).
