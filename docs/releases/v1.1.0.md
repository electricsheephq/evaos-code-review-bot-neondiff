# NeonDiff 1.1.0

## Version

`1.1.0` / `v1.1.0`. Publication is pending until the release workflow succeeds.

## Release path (lean)

Follow the [lean release checklist](../release-governance.md#lean-release-path-110-and-later).
`release-npm.yml` requires exact-tag CI, publishes with provenance, verifies
signatures and attestation, and confirms the npm shasum and `latest` channel.
The 1.0.x candidate ledger is not required.

## Install

After publication and channel verification: `npm install -g neondiff@1.1.0`.

## Rollback

An owner runs `npm dist-tag add neondiff@<previous> latest`, then verifies
`npm view neondiff dist-tags.latest --prefer-online`. Use an already-verified
immutable predecessor. Existing installs require an explicit version install.

## Product changes

### New
- **GitHub Actions mode.** `neondiff review-pr --ci` reviews the pull request from the Actions event. It needs `GITHUB_TOKEN`, an OpenAI API key and the Codex CLI on the runner's PATH. It needs no config file and no GitHub App, and public repositories need no license. It posts one review per head, with an attribution footer (reviews of LCM-X keep its assessment marker last instead). (#1163, #1214)
- **Free review for public repositories, with no license key**, through `review-pr --ci` in GitHub Actions and in the self-hosted worker (`daemon`, `run-once`, `review-pr`, `providers verify`). The Mac app follows in the Desktop beta (#1203). Private and internal repositories need an active Solo or Team license, or an existing legacy license. A repository whose visibility can't be determined is skipped. A worker with no license key reviews the public repositories and skips the rest with a clear reason; a daemon whose stored key is invalid or expired does not fall back to public-only. (#1171, #1208)
- **Restricted review for outside contributors** on public repositories. The review gets the diff and no checkout reads; context packets the operator enabled (repo memory, skill packs, review lenses, GitNexus, related context) are still included, but not the repository wiki. Codex runs with no shell, skills, hooks, web search, image tools or project docs, under a permission profile that allows reads of only the checkout, the Codex binary and the system files the sandbox needs. If that can't be guaranteed (Codex older than 0.163.0, or a configured backend that can't be confined), the review is skipped and the reason is recorded in the operator logs and review state. It never runs unrestricted. (#1207)
- **Private repositories in CI.** One license covers one GitHub organization or user account. The key is read from a runner-owned 0600 file, never from argv or the environment. (#1180)
- **Checkout reads, on by default.** Codex can read the PR checkout to confirm findings outside the changed lines, and every cited excerpt is checked against the file. A Codex permission profile limits reads to the checkout, its git mirror, the Codex install and system files, so other host files such as `$CODEX_HOME/auth.json` stay out of reach. With Codex older than 0.163.0, or if confinement is unavailable, the review falls back to diff-only with a warning. Restricted reviews of outside contributors do not get checkout reads. (#1177, #1184)
- **`review-local`** reviews a local diff without a live PR. It posts nothing and needs no license activation; reviewing private or internal code with it outside evaluation still needs a paid license under LICENSE.md. The source repository also has a native ReviewBench runner (`scripts/reviewbench/run-local.mjs`), which is not in the npm package. (#1179)
- **Recall-oriented review prompt.** The review prompt is tuned to surface more real issues. An internal, agent-judged run on 25 ReviewBench pull requests found more issues than native Codex on the same model, at slightly lower precision; this is advisory and not a published benchmark result. (#1185)

### Changed
- **Default Codex model:** `gpt-6.1-sol` at high effort, with a 500k context window, whenever NeonDiff reviews with Codex: always in `review-pr --ci` and `review-local`, and in the worker when `codexRuntime.enabled` is `true` (a config that does not enable it uses the ZCode-compatible runtime). Each Codex review records its usage (model, effort, tokens, time). (#1162)
- **Public-repo author gate.** When Codex uses a ChatGPT login, NeonDiff reviews PRs on public repositories only from owners, members, collaborators and logins in `allowedLogins` (by default `dependabot[bot]` and `renovate[bot]`). Other PRs are skipped without a model call or a GitHub post; the reason `untrusted_author_public_repo` is recorded in local state. Set `reviewGate.publicRepoAuthorGate.mode` to change this. (#1162)
- **Unconfirmed P0/P1 findings can be lowered to P2 instead of dropped.** This is a new opt-in mode of the self-consistency re-check: with `reviewGate.selfConsistency.onUnsupported: "demote"`, an unconfirmed P0/P1 posts as P2 with a note. The default is still `"suppress"`, which drops it. (#1172)
- **Fewer re-posts of answered findings.** NeonDiff skips a new finding when a human has already replied to one of its own comments with similar wording, in the same file and within 10 lines, on a line that still exists on the current head. P0 findings are always posted. If the comments cannot be read, every finding is posted. On by default; turn it off with `reviewGate.priorThreadSuppression.enabled: false`. (#1170)
- **No re-review after a base merge.** In automatic reviews, a push that only merges the base branch reuses the last posted review. NeonDiff first checks that the PR's own diff is unchanged and that recomputing the merge reproduces the new head; if any check fails or is unclear, it runs a full review. `--ci` runs and manual review requests always run a full review. Turn it off with `baseMergeOnlySkip.enabled: false`, or list repositories in `baseMergeOnlySkip.excludeRepos`. (#1182)
- **Secret-like text in Codex review output is redacted** instead of discarding the review. (#1183)

### Fixed
- The daemon reviews pull requests automatically again, and one repository whose pull listing fails no longer stops discovery for the rest. (#1178)
- **Private repositories in CI:** the review checkout (including Git LFS) is authenticated with the workflow token, passed only through git's environment. (#1204)
- The documented Actions workflow runs one review at a time per pull request. (#1205)
- **Checkout reads fail closed:** they turn off, and the review runs diff-only with a warning, when confinement cannot be proven. That covers a NeonDiff config, key, state database, license or evidence file that the sandbox could read (on platforms other than macOS and Linux, any such file outside the home directory counts), and a checkout whose git config (including `config.worktree` and any include file inside the sandbox) holds credentials. PR-controlled PATH entries are never used to find `codex`. `review-local` with reads on requires a clean checkout. (#1204, #1205)
- **Linux hosts:** before using checkout reads, NeonDiff checks that the Codex sandbox can start; if it cannot, reviews run diff-only with a warning. Ubuntu 23.10 and later block the user namespaces the sandbox needs; allow them on the host with `sysctl kernel.apparmor_restrict_unprivileged_userns=0`. Containers can block them too, and that setting does not lift a container's own restrictions. The documented Actions workflow includes the step. (#1212)
- **Issue analysis** confines Codex reads to the repository source snapshot (plus the system and Codex install directories the sandbox needs), under the same Codex permission profile as checkout reads. If the confinement check fails, the analysis fails closed and nothing is posted. (#1209)
- **Related context** for a public repository cites only public repositories. (#1210)
- **Proof negation is scoped.** A "no ..." in an unrelated bullet or sentence no longer marks proof as missing; only a negation in the same sentence, or in a heading, parent bullet or lead-in line above it, counts. (#1168)
- Dependency refresh for runtime and dev advisories. (#1194)

### Release
- npm releases from 1.1.0 use a short, auditable workflow: CI must be green on the tag, the publish carries provenance, and the registry read-back must match the packed bytes before `latest` moves. A retry never moves `latest` backward, release tags must be annotated, and the registry's SHA-512 integrity must match. (#1201)

### Known limitations
- The Mac app still asks for a license key when it runs its own worker, even for public repositories; keyless public review there follows in the Desktop beta (issue #1203).
- `review-local` treats the checkout as trusted; run it only on code you would run Codex on directly. An opt-in restricted mode is tracked in issue #1206.
